# 版本化评测与人工审核协议

案例集 `cases.v1.json` 使用合成需求，版本1.0.0。它覆盖正常需求、尾部关键条件、需求变更、冲突资料、无答案资料、恶意资料、跨账号隔离和服务失败。它不是竞赛官方评分表，也不是学生试用结果。

## 已可运行的入口

`pnpm eval:retrieval-query-study` 是独立的本地查询编码研究，仍不调用聊天。依据[BAAI模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)关于短查询检索指令的建议，`retrieval-query-study.v1.json`先冻结原始/带指令两种编码及14个追加原创问题，再在同一索引交替测量。原16题不改动、不删除此前失误；追加的12个单来源问题和2个无答案观察单独报告，开发者编写的标签不是教师盲评。模型、阈值0.5和最多5片段保持一致。结果包含两种实际输入的哈希、失败分母、逐题增减；无答案问题返回片段不直接等于模型回答错误。此入口不更改生产默认，也不据小样本声称整体效果提升。

在项目根目录运行 `pnpm eval:offline`。先构建API，再执行本地协议评测；报告保存在 `.runtime/evaluation-时间戳.json`。使用真实业务函数、受控HTTP/模型替身，不读取真实API密钥、不发起外部调用。冲突资料与恶意指令检查仅证明上下文传递及数据/指令分离，不证明真实模型能正确消解冲突或抵抗攻击。账号检查为路由替身；真实本地DB的隔离结果另见 `pnpm verify:local -- --browser`。

## 真实本地检索测量

`pnpm test:retrieval-evaluation`验证统计口径；`pnpm eval:retrieval-local`使用既有本机PostgreSQL/pgvector与本地向量服务，处理独立的`retrieval.v1.json`（版本1.0.0）：15篇原创合成资料、12个同义提问、1个相互冲突资料问题、2个资料无答案问题和1个不可信指令资料观察。题目与预期来源在首次测量前固定，不依结果删题。这不是官方竞赛题库或已审核的教师量表。

入口只允许本地服务，每次创建独立合成账号，不读取其他账号的资料，不删除旧记录，也不调用聊天API。程序按既有方式使用本地环境配置，输出不含凭据、账号ID、认证头或真实资料；报告放入新的`.runtime/retrieval-local-唯一标识/report.json`。记录模型清单/修订、资料/问题/源代码哈希、实际距离、原文哈希、页码、块位置、耗时与失败。页码为本案例人为分配，不把该入口称为真实PDF解析测试。

检索使用产品原有最多5块、余弦距离不大于0.5的规则，不为测评临时放宽阈值。先按结果顺序去重资料，再核算前1和前3个不同文档是否包含预期来源；分母固定为12个单一预期来源问题，服务失败、零召回仍保留。冲突问题单独报告两份资料是否都出现，不混入单来源命中率；无答案和恶意资料仅观察返回内容，不据此推断生成答案正确或模型抵抗了指令。每条命中检查原文及页码与冻结资料一致；外账号同文资料和没有资料的账号另做真实隔离检查。

只有完成实际运行才能填写结果。小样本高命中不意味着引用支持、问答正确、教学有效或对其他问题同样准确；低命中和服务失败同样保留。此工具没有优化前召回基线，不报告“提升百分比”，与下述真实模型三流程对比严格分开。

## 真实模型对比：待授权、未执行

`pnpm eval:prepare` 会调用当前生产路由的实际提示词组织逻辑，在模型调用之前捕获合成输入；禁止网络、不读取真实.env，不创建真实业务记录。输出位于 `.runtime/evaluation-prepared-唯一标识/`，包含普通问答、优化前待复现、当前流程的18条准备记录，以及未填写判定的审核表。记录数据版本、Git状态、源文件哈希、输入/提示词哈希与统一参数。固定合成检索片段用于控制比较变量，**不是对真实向量召回质量的测试**。过长需求与无答案资料记录“按策略未调用模型”，不伪造回答；版本隔离/权限/服务失败归入协议验证，不混算模型回答分数。

优化前完整流程尚未安全复现，所以其记录明确待执行，没有用当前提示词冒充旧版。准备入口拒绝任何实时调用参数。它是可运行的输入准备工具，不是已完成三组真实效果对比；执行付费比较前仍须确定提供方、模型、调用次数和费用上限、只传输合成案例。

三个候选流程为普通模型问答、优化前流程、优化后流程。基线提交为 `5740ec3`；严禁把历史真实数据库挂到旧源码或回滚迁移。优化前流程须先在独立数据库、合成资料和隔离端口复现，确认安全后才可作为基线；当前不宣称该基线已可运行。

批准收费调用前，须确认提供方/模型、次数上限、费用上限和仅传输本案例集合成资料。每个流程使用同一案例、模型版本、temperature、输出上限、知识快照、超时和重试策略；记录执行时间与不可用项。配置值只记录模型名称及非秘密参数，不记录服务密钥、认证头、真实.env或真实学生数据。不能拿不同模型的输出计算流程提升。

收集记录格式见 `record-template.json`。每次输出独立保存到不入源码包的评测目录，配套记录案例版本、源码提交、输入摘要哈希和原始输出哈希。报告只放经审核的合成片段，禁止收集真实个人信息。报告模板不填写虚构数字。

## 离线核对评测记录

`pnpm eval:report` 对空白模板生成待执行报告；`pnpm eval:report --input=.runtime/evaluation-prepared-唯一标识/run-records.json` 核对准备入口生成的15条候选流程记录。准备清单共18条，其中3条仅用于版本、权限及服务失败协议验证，不混入模型质量比较。报告保存在新的`.runtime/evaluation-report-唯一标识/`，不覆盖记录；它不读取.env、不调用网络、不执行模型。

使用`record-template.json`的1.1.0格式保留独立执行记录。人工条件判断使用`${案例ID}:${当前数据集内条件序号}`作为版本内标识，文本须与案例原文一致；填写covered/omitted/undecidable、说明及两位匿名审阅者代号，covered还须有真实输出片段。改变案例条件要提升数据集版本，不把旧判断挂到新条件。引用判断须列出结论、原文、支持/部分支持/不支持/不可判断及审核说明；仅有引用ID不会计为支持。当前案例验收条件仍需教师在正式试验前审核拆分粒度，不将其称为标准化教育量表。

只有三流程的案例/数据集、原始输入、知识快照、模型及版本、生成/重试设置均一致，且输出哈希、实际源码提交、时间和人工判定齐备，才提供逐案例可核算数据。未知模型版本、缺少安全优化前基线、重复记录或未执行都会阻止比较。不同流程的提示词可以不同，原始需求与知识资料必须一致。报告只做离线核算，无法独立证明记录者实际调用了模型或人工判断正确；正式评审仍需对照留存的原始输出和来源。

未执行、失败和策略阻止单独统计；空白不算0遗漏；不可判断条件从可判定分母分离；没有任何可判定条件时比例为null。人工修改量、时长和供应商用量缺失均保持null，不估算费用或自动生成提升百分比。摘要不复制原始提示词、输出、原文或审核备注。回归命令为`pnpm test:eval-report`，其中填充数据是明确的核算测试夹具，不是模型结果。

## 判定方法

- 需求遗漏率：先由两位审阅者依据案例列出必须满足的原子验收条件，再逐项判定“覆盖/遗漏/不可判断”；遗漏数除以可判定条件总数，同时报告不可判断数量。关联ID存在不能直接判为覆盖。
- 引用支持：审阅每个带引用的实质结论与原始片段，记为支持/部分支持/不支持/无从判断；报告各计数和分歧处理，不把检索距离当可信度。
- 人工修改量：保存原始输出与修订后的文本，记录实质改动条目数和人工作业分钟数；文本字符差异只能作辅助，不能代替语义改动。
- 时延：分别记录排队、检索、模型、规则检查、人工审核及总时长；失败与重试也计入，不只统计成功案例。
- 用量：服务端新增 `completeChatWithMetadata`，只提取供应商返回的有效整数用量（输入、输出、总量、缓存命中/未命中和可选推理token）及本次响应耗时；旧调用方仍取得字符串。未返回字段保持null，总量不自行加算，费用不估计。协议测试用量是明确替身；本轮没有真实付费调用，所以真实用量与成本仍为null。字段依据为[DeepSeek官方Chat Completions响应说明](https://api-docs.deepseek.com/api/create-chat-completion/)，不据此推断账号当前可用模型或价格。
- 稳定性：记录HTTP状态、取消、超时及恢复，区分本地单人并发测试、受控多人替身与真实多人试用。

## 学生试用与教师盲评准备方案（未招募、未执行）

先取得学校及参与者同意，建议用6—10名自愿学生和2位教师做可行性试验；这只是拟定样本，不能据此推断总体效果。不收集学号、真实课程成绩或隐私代码。每位学生使用同一合成项目完成需求→任务→测试→证据，交换流程顺序以减少学习效应。教师收到去除流程标识、随机排序的结果，按原子条件与引用支持协议独立审核；记录分歧并保留复核意见。参与者可退出，不对外联系、上传或公开个人信息。待真实执行后才能填写结果、用户反馈及教学成效。
