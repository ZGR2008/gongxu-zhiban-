# 版本化评测与人工审核协议

案例集 `cases.v1.json` 使用合成需求，版本1.0.0。它覆盖正常需求、尾部关键条件、需求变更、冲突资料、无答案资料、恶意资料、跨账号隔离和服务失败。它不是竞赛官方评分表，也不是学生试用结果。

## 已可运行的入口

在项目根目录运行 `pnpm eval:offline`。先构建API，再执行本地协议评测；报告保存在 `.runtime/evaluation-时间戳.json`。使用真实业务函数、受控HTTP/模型替身，不读取真实API密钥、不发起外部调用。冲突资料与恶意指令检查仅证明上下文传递及数据/指令分离，不证明真实模型能正确消解冲突或抵抗攻击。账号检查为路由替身；真实本地DB的隔离结果另见 `pnpm verify:local -- --browser`。

## 真实模型对比：待授权、未执行

三个候选流程为普通模型问答、优化前流程、优化后流程。基线提交为 `5740ec3`；严禁把历史真实数据库挂到旧源码或回滚迁移。优化前流程须先在独立数据库、合成资料和隔离端口复现，确认安全后才可作为基线；当前不宣称该基线已可运行。

批准收费调用前，须确认提供方/模型、次数上限、费用上限和仅传输本案例集合成资料。每个流程使用同一案例、模型版本、temperature、输出上限、知识快照、超时和重试策略；记录执行时间与不可用项。配置值只记录模型名称及非秘密参数，不记录服务密钥、认证头、真实.env或真实学生数据。不能拿不同模型的输出计算流程提升。

收集记录格式见 `record-template.json`。每次输出独立保存到不入源码包的评测目录，配套记录案例版本、源码提交、输入摘要哈希和原始输出哈希。报告只放经审核的合成片段，禁止收集真实个人信息。报告模板不填写虚构数字。

## 判定方法

- 需求遗漏率：先由两位审阅者依据案例列出必须满足的原子验收条件，再逐项判定“覆盖/遗漏/不可判断”；遗漏数除以可判定条件总数，同时报告不可判断数量。关联ID存在不能直接判为覆盖。
- 引用支持：审阅每个带引用的实质结论与原始片段，记为支持/部分支持/不支持/无从判断；报告各计数和分歧处理，不把检索距离当可信度。
- 人工修改量：保存原始输出与修订后的文本，记录实质改动条目数和人工作业分钟数；文本字符差异只能作辅助，不能代替语义改动。
- 时延：分别记录排队、检索、模型、规则检查、人工审核及总时长；失败与重试也计入，不只统计成功案例。
- 用量：只记录供应商实际返回的输入/输出token与可核对费用；当前聊天适配器只返回内容，不提供用量数据，所以为null，禁止按字数虚构token或成本。
- 稳定性：记录HTTP状态、取消、超时及恢复，区分本地单人并发测试、受控多人替身与真实多人试用。

## 学生试用与教师盲评准备方案（未招募、未执行）

先取得学校及参与者同意，建议用6—10名自愿学生和2位教师做可行性试验；这只是拟定样本，不能据此推断总体效果。不收集学号、真实课程成绩或隐私代码。每位学生使用同一合成项目完成需求→任务→测试→证据，交换流程顺序以减少学习效应。教师收到去除流程标识、随机排序的结果，按原子条件与引用支持协议独立审核；记录分歧并保留复核意见。参与者可退出，不对外联系、上传或公开个人信息。待真实执行后才能填写结果、用户反馈及教学成效。
