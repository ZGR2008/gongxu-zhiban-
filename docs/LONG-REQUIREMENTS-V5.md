# v5 长需求规划：实现、证据与恢复

本轮接通的是“分段规划→合并审核→正式任务”。已有单次生成仍以20000个UTF-16代码单元为安全边界，需求存储上限50000不变。测试生成、项目文档及结合需求的代码审查尚未接入分段处理，超过其限制时明确阻止，不能称为全链路支持长需求。真实模型生成质量待验证：用户明确决定本轮不新增收费调用。

## 原文与拆分方案

新增022迁移，保留原始确认需求、版本、全文SHA-256、连续半开范围[start,end)和各段哈希；位置按JavaScript UTF-16计数，不把emoji中间作为边界。默认每段4000，人工可修改边界，每段最多6000、最多20段。跨段单条条件会携带完整原文，不截断尾部。

原子条件有稳定标识、原文范围、简述、验收/上下文分类、依赖、跨段说明及重复范围说明。改变范围时标识改变；仅移动片段边界而原文范围未变时保持标识。方案修订和历史保留在库内，任何修改都使审核失效。必须覆盖全部非空原文、分类全部条件、解释跨段/重叠并检查依赖无环，才能记录人工审核。全文连续与ID齐全仅是结构证据，不证明拆分后的语义正确。

实现：`apps/api/src/long-plan/domain.ts`、`store.ts`；界面复用Agent页的`LongRequirementPlanning.tsx`。原v4只读分段审阅仍保留。

## 持久化作业与费用边界

作业绑定账号、项目、确认需求、拆分方案修订、提示词版本`long-plan-fragment-v1`及非秘密模型参数。每段保存状态、实际输入/检索原文、候选任务、原始回答、实际返回用量和错误。凭据不进入快照。修改应用模型配置后，旧作业不能悄悄换模型续跑。

数据库会话锁限制整个实例群同时生成1段；最多8个活动作业，同一账号最多2个。重复创建由请求键及方案修订唯一约束消除。点击“启动/继续”才调度；服务启动、页面读取和断点恢复检查都不会自动收费。每次尝试在发送前写入数据库，工作器用租约和版本检查阻止迟到结果写入新的状态。

超时、断连、取消或服务中断不能证明提供方未处理请求，因此记为不确定，保留已有片段，停止后续调用。没有自动重试。人工在理解可能重复费用后选择某段重试，最多3次尝试，有有限退避；随后仍需显式恢复。429、服务拒绝、格式错误和输出截断均不会伪装为成功。截断回答及用量保留供审阅。纯空白片段作为原文记录保存，不伪造模型任务。

## 实际输出与合并审核

每段返回真实业务候选字段：任务标题、阶段、描述、验收方法、依赖、条件标识、来源标识和未决问题。RAG只使用该账号检索结果，原文供核对；无资料明确提示，不补造引用。提示词提供完整当前段和所需跨段条件；超过单段提示预算时调用前阻止，不截断。

合并保留全部分段结果和修改历史。结构检查包括漏掉的验收条件、未知关联、循环依赖及最多80个正式任务；候选超过80必须人工合并，不能悄悄丢任务。提示项包括重复标题、跨段依赖、候选冲突、无依据、引用需要核对及未决问题。冲突检出是启发式提示，不能替代全局语义审查；引用存在不等于支持结论。

人工修改某段时单独标为`human_correction`，不覆写原始模型尝试。全局草案允许保存未完成的JSON以避免丢输入，但错误草案不能审核/采纳。每项审核提示必须填写处理说明，并作整体审核；后来修改草案会清除审核。

## 事务采纳与后续证据

采纳在事务内锁定项目、方案和作业，复核当前确认需求、方案修订、作业修订和审核草案哈希。新版需求确认后，旧作业不能覆盖新计划；重复采纳返回同一次运行，不重复创建任务。写入正式任务及“建议”关联，任务处于待办。追踪页面仍需人工确认关系、建立测试并登记实际执行说明。人工登记结果明确标注来源，不是自动沙箱执行。

需求变更后原来的任务、测试、执行记录和文档仍按旧版保存；旧通过不会冒充新验证。新增长规划复用已有追踪闭环，没有自动替人确认测试或交付。

## 数据结构与安全升级

022仅增加拆分方案/历史、作业、片段、尝试、事件及任务条件建议表、索引和约束，不修改旧业务记录，不清库。先构建API再运行现有迁移器；迁移器可重复运行。已在隔离空库应用001—022并检查重复执行。本机业务库已增量应用022，旧文件和旧交付包保留。

恢复顺序：停止发起新作业；正常关闭API；重启后读取作业会暂停中断/旧工作器记录，不自动重发。不确定尝试先核对已有输出和提供方记录，再决定人工修订或明确重试。更换需求或方案后新建作业，旧作业留作审计。若回到v4代码，保留022新增表即可，不能为了回退删表；重新进入v5后先核对作业版本。原有数据库备份按维护者既有流程处理，本轮未读取或导出真实业务数据。
