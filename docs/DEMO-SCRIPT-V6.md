## 0:00—0:40 真实痛点（40秒）

逐字稿：

大家好，我的作品是工序智伴，面向软件工程实训。做项目时，最容易忽略的往往不是少写一个页面，而是需求已经变了，任务、测试和报告还停在旧版本。比如校园借用原来允许七天，后来改成三天，一份旧的通过记录还能证明现在的系统正确吗？工序智伴要帮助学生回答：哪里受影响，还缺什么证据，下一步应该由谁核对。今天使用原创合成案例，不展示同学的真实作业。

## 0:40—1:15 解决方案与角色边界（35秒）

页面：同站点已授权学生/教师工作台，使用两个合成会话；点击：身份菜单（只含授权角色）。预期：学生任务与教师提交目录不同。

逐字稿：

平台把需求、任务、测试和交付依据放在同一条链上。学生在自己的私有项目里练习，教师发布任务、给反馈，管理员管理授权和额度。身份不是在浏览器里选一个名字就能获得，后端每次检查角色和班级。教师看不到学生未提交的草稿，管理员也没有隐含的私人项目阅读权。共享发生在学生主动确认提交之后，而且共享的是那一刻的固定快照。

备用：真实账号尚未授予教师时，只用已验证隔离合成账号；不要临时提权或猜账号。

## 1:15—2:05 从教学任务到个人项目（50秒）

页面：`/teaching`→`/classroom`；点击：教师任务草稿→确认发布；学生领取→打开项目。数据：校园借用，禁止申请人自批、借用期限、归还验收。预期：一个新私有项目；重复领取不多建。

逐字稿：

教师先保存任务草稿，确认后才向班级发布。学生领取任务后，平台创建一个新的私有实训项目，不会把以前的个人项目自动归到班级。这里要实现设备申请、教师审批和归还验收。我们特别保留“申请人不能审批自己的申请”，因为这样的限制很容易藏在需求末尾。领取和提交都考虑重复点击，服务端会识别同一次操作。接下来学生可以在原有项目工作区分析需求、查看计划、设计测试，教学流程复用了这些真实模块。

备用：领取迟迟未响应时刷新任务状态核对已有项目，不连点创建；如隔离服务中断，用已有截图说明“此前实测”，不称现场成功。

## 2:05—3:15 AI计划、知识与长需求（70秒）

页面：Agent、知识库、长需求；点击：查看已保存计划/工具记录→展开公共原文→长需求已审阅方案和作业记录。数据：51篇教学集合；长案例49781字符；演示计划/输出使用已标记协议替身，非新真实调用。预期：段范围、条件、原始输出、合并待审、真实状态。

逐字稿：

AI在这里的作用是提出可检查的候选方案，而不是给一个答案就结束。计划包含任务、验收方法和需求关联，工具调用有结果记录，人工审核之后才能采纳。知识库已经导入五十一篇原创教学资料，登录用户共读一份索引，私人上传仍保持私有。这里展开的是实际检索片段，引用存在仍不代表它支持所有结论。对于长需求，我们保留全文位置、哈希、稳定条件和跨段依赖，逐段生成、持久保存，再检查遗漏和冲突。现在展示的长规划输出是协议测试替身，验证的是流程与恢复，真实生成质量尚待新的授权；没有把截断文本包装成完整计划。

备用：本地向量服务慢时读已存原文并说明未完成本次检索；模型慢/失败不新增调用，切到已有作业记录解释暂停、不确定及人工恢复边界。

## 3:15—4:20 测试证据与需求变更（65秒）

页面：项目测试/追踪/文档；点击：当前需求→用例来源修订→执行说明→确认三日新版→追踪缺口。预期：历史通过不计当前版本；文档也提示来源变化。数据：人工合成登记，未执行状态保留，禁止伪造真实代码运行。

逐字稿：

这条测试对应借用期限，也关联到具体任务和需求原文。模型建议关联、人工确认关联和执行证据是三个层次。我们没有在不安全的服务器上执行学生任意代码，测试结果由操作者如实登记；未执行就显示未执行。现在把期限从七日改成三日，旧版本的通过不会直接算作新版验证，相关任务、测试和文档需要重新核对。同一个需求版本下，如果测试或人工关联后来又变了，原报告的依据也可能过期。界面给出缺口和下一步，不自动替学生把关系勾成通过。

逐字稿：

备用：时间不足时以预先准备的第二次合成提交展示对照，说明它是既存记录；不能把返回失败说成验收成功。
