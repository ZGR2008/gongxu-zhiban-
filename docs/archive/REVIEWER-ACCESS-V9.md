## 两个不同交付对象

- 脱敏源码 ZIP：用于离线检查源码、模板、迁移、测试和说明。排除 `.git` 后没有真实 Git 历史；ZIP 的可解压和构建通过不能替代比赛仓库要求。
- 评审仓库：必须保留真实历史并按官方允许方式使评审者访问。源码包在副本中发生的脱敏应有映射和说明；不能重建虚假的提交历史、改写时间、造成人工贡献或把最终 ZIP 上传为单一提交后称其完整历史。

若既有历史含凭据或个人信息，先暂停对外分享，记录问题并获得处置授权；本流程不授权重写历史、公开历史、撤销凭据或扩大访问范围。历史扫描只输出风险类型和必要位置，不输出秘密值。干净的当前工作树不能证明所有历史对象均可公开。

## 可复核的复现指引

以下命令仅供已确认目标后的评审副本使用，不在原项目目录覆盖文件。`<已确认仓库URL>`和`<最终提交号>`须由团队据实填入；私有认证由评审者自己的客户端完成，不向团队索要或发送凭据。

```powershell
git clone <已确认仓库URL> gongxu-zhiban-review
cd gongxu-zhiban-review
git rev-parse HEAD
git rev-parse --is-shallow-repository
git cat-file -e '<最终提交号>^{commit}'
git log --format='%h %ad %s' --date=iso-strict
pnpm install --frozen-lockfile
pnpm verify
```

不要用`--depth=1`再宣称完整历史；不要修改全局 Git 身份、关闭证书检查或将令牌拼进可记录的命令。若正式评审目标不是默认分支，在新的评审副本中核对后切换到该提交；不在原开发目录重置或覆盖工作。

运行指南以最终 README 和`STARTUP-AND-VERIFICATION.md`为准。当前清单声明 Node 22+、`pnpm@11.25.0`、PostgreSQL＋pgvector；Python及其依赖用于相应验证与本地向量服务。评审者在独立环境从不含秘密的模板建立本地配置，聊天配置可留空，此时页面应明确未配置。

独立数据库准备完成后可执行：

```powershell
pnpm --filter @gongxu/api db:migrate
pnpm build
pnpm dev
```

检查网页`http://127.0.0.1:5173`与 API`http://127.0.0.1:3001/ready`。Embedding 为独立可选进程，其依赖、权重及启动按`apps/embedding/README.md`执行，未准备就记录检索未验证，不把聊天接口当向量接口。合成隔离数据库、受控浏览器及可访问性可分别使用`pnpm verify --suite=database`、`--suite=browser`、`--suite=accessibility`，先核对对应运行条件。

不得执行真实模型评测脚本、删除已消费授权锁、使用`--with-ai`或以旧授权追加调用。本地现有模型回答可离线审核，但不能替代此评审环境的实际接口验收。

## 结果与提交状态

复核者记录：姓名或授权角色、日期、仓库目标与提交、环境、实际操作、结果、证据位置、缺失依赖和整改复核。不要只填“可以访问”而没有非所有者身份范围。团队成员自行使用非所有者身份完成一次访问也不能证明官方评审身份已经获权，二者分别记录。

1. **本地检查完成：**只描述本机执行过的检查和证据。
2. **具备提交条件：**适用规则、资格、必要材料和评审访问都有足够依据后，由团队逐项复核判断；不能从 ZIP 构建成功直接推定。
3. **已实际提交：**必须实际提交并核对平台条目、文件版本、时间及回执。没有回执时保持未核实，不把推送或上传中当作提交成功。

本文件仅准备操作流程。外部上传、推送、公开或分享权限变更、部署、凭据配置及官网提交仍需单独明确授权；未执行项继续保持待核验。

## 建立或整理正式评审仓库的操作顺序

1. 先确认目标平台、所有者、准确地址、Public或官方私有评审方案、要分享的真实历史范围与团队元信息。此刻只准备，不创建远端或修改权限。
2. 在本地核对真实历史、分支、标签、锁文件、模板与README；提交作者信息不等于真实贡献证明。对准备分享的完整历史另做不输出秘密值的审查；发现凭据或私人资料先暂停，不擅自改写历史。
3. 团队批准后，由所有者在平台新建空仓库或确认已有仓库；已有远端先比对，不强制推送、不用ZIP初始化后声称具有完整历史。
4. 只有明确授权后才绑定已确认URL并推送选定分支及必要历史；不把令牌放命令、不更改全局身份。
5. 依据官方私有评审身份完成授权，或按获批公开范围设置访问。由非所有者按R03—R11检查，记录实际提交号。
6. 固定源码提交、PDF、视频哈希后，由参赛负责人经官网提交并核对回执。推送成功与比赛提交成功分别记录。
