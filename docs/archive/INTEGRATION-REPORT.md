## 实际跑通的业务链路

1. 注册两个测试账号，创建项目与需求版本，保存、重新读取和确认需求。
2. 确认前禁止规划，确认后禁止覆盖原需求内容；另一个账号不能访问项目、任务或需求。
3. 上传文本及真实 PDF，解析、分块并持久化；向量化前保持“待向量化”状态。
4. 调用本地真实模型建立索引，执行语义检索；返回实际文档片段和 PDF 页码，跨账号检索返回空结果。
5. 调用 DeepSeek 分析需求，保存生成记录；RAG 回答返回本账号实际检索得到的来源。
6. Agent 检索知识、生成任务计划、执行依赖与引用规则校验，进入待审核状态。审核前没有任务，确认后创建任务及依赖；重复确认被拒绝。
7. 提交具有语法错误的 TypeScript 样例，确定性语法诊断与未经运行验证的 AI 建议分别保存。
8. 生成正常、边界、异常三类测试用例，初始状态均为未执行；登记阻塞状态后修改用例，旧执行状态被清除。
9. 基于实际需求和测试统计生成测试报告，编辑后导出，导出内容与保存版本完全一致。
10. 成长统计与当前账号的实际项目、任务、用例和操作事件匹配；退出重新登录后数据仍可读取。

数据库回查显示该接口联调项目实际保存了 **12 个任务，其中 8 个带知识来源引用；11 条测试用例均为未执行；1 份项目文档**。这些数量是该测试样例的实际结果，不是硬编码的产品展示指标，也不表示已经完成借阅系统的开发和测试。

浏览器检查另行覆盖注册、创建项目、刷新后保存需求、确认需求、文本入库、建立索引、实际检索、Agent 进度刷新、审核确认及任务状态持久化。检查项目、知识库、成长、需求、Agent、审查、测试、文档路由在移动宽度下没有整页横向溢出。退出登录后，原会话访问身份接口实际返回 401。
