## 分类方法与误报来源

分类器保留旧版宽泛表达式以准确复现候选，不删除原始 v9 记录。所有疑似值只在程序内存中参与有限模式判断，不打印、不存入新报告、不产生可猜测原值的值哈希；查看上下文时先遮蔽字面量，只检查代码结构。

1. **HTML 条件表达式误报。** 旧表达式在自动填充属性的条件分支中把单词片段误认为密码字段赋值。分类同时检查公开 HTML 属性词汇和所在行属性结构，不按“网页代码”一概放行。
2. **拼接语法误报。** Python 注释说明和临时目录测试将字符串与变量拼接；旧表达式匹配了拼接语法片段，并没有取得一项真实配置值。测试模板的判断同时要求 unittest、临时目录与写入模板的结构。
3. **空模板跨行误报。** 旧表达式允许空白跨换行，在 `apps/api/.env.example` 的空配置之后吃掉下一行。只读取明确的示例模板，未打开真实 `.env`。
4. **测试与本地代理占位。** 除显式合成标记外，还核对测试运行器、替身注入、保留测试域名、本机监听服务或命名完成函数的传递位置。长需求回归的命名替身被明确传入路由并统计调用，因此没有仅凭变量名放行。真实评测脚本中的被命中字段属于本地代理配置，不能据此推断该脚本处理的其他真实凭据也被检查过或允许公开。
5. **内存认证用例。** 认证测试使用本文件定义的 Map 假存储并注入注册／登录请求，命中用于合成测试账号的输入。没有查询或改动任何实际账号。

安全保守分支仍然存在：仅文件名像测试、没有足够上下文的赋值归为“无法判断”；有提供方凭据形状的值，即便出现在测试或带合成字样，也归为“可能真实”，不发起调用验证。不得通过放宽分类规则把所有未知值变成绿色。
