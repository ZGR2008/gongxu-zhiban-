# 教师任务版本、教学验收与恢复

解决的问题：原任务草稿保存只创建新记录；发布后无法继续编辑；学生已领取要求没有独立版本。新实现保留原任务 ID，用修订校验更新草稿，并将发布版本固定保存。

## 从草稿到明确变更

1. 首次保存通过请求键创建一个草稿，重复点击仍为同一个任务。之后用 PATCH 更新；携带读取时的修订，旧窗口返回409。输入保持，先读取服务器版本比较，再明确合并保存。
2. 发布后原版本不可覆盖。教师从目录“编辑或修订任务”打开，创建下一版本草稿，填写至少10字的变更说明，并选择仅之后新领取适用，或向已有领取者提供变更建议。
3. 旧领取固定原版本，个人项目不会自动改写。新领取绑定最新已发布版本；向已有学生提供的变更会明确提示比较。学生选择采纳或保留并说明，形成变更处理记录。
4. 已提交或已验收状态不允许学生自行修改任务适用版本。需要教师按流程退回后再处理。历史提交快照仍保存当时的要求、任务、测试和文档，不会因任务发布新版而重写。
5. 采纳任务新版不等于个人需求已修订。学生必须手动保存并确认需求，旧任务、用例与文档继续按版本提示待复核。

## 权限矩阵

|操作|学生|教师|管理员|
|---|---|---|---|
|私人项目与未提交草稿|仅本人|无隐含读取权|无隐含读取权|
|已发布任务与版本|有效成员所在班级|本人授权班级|不因管理员身份取得班级正文权限|
|任务草稿编辑与发布|禁止|本人班级，修订与状态校验|需要另有教师身份及班级归属|
|明确提交固定成果|本人领取，当前需求与来源指纹一致|不可代替学生提交|不可代替学生提交|
|评阅与发布反馈|仅查看本人已发布反馈|授权班级的已提交快照；AI草稿需人工确认|不因管理员身份取得评阅权|
|班级进度|无教师统计接口权限|本人班级有效成员状态计数|不隐含开放统计或正文|
|账号、角色、额度|禁止|禁止|既有授权管理员，操作留审计|
|公共课程读取/维护|登录只读|登录只读|授权维护；个人资料仍不公开|

后端逐次检查当前身份和班级归属。撤权与离班生效后旧窗口请求同样被拒绝，保留原个人项目、历史提交和操作记录。此前指定真实账号的角色授权已经单独执行并留有本地审计；这不开放其他账号私人资料。不能将其历史授权当成任意新账号提权许可。

## 真实缺口与例外验收

班级进度按未领取、已领取未提交、待评、退回、已验收统计，只读取授权成员的领取状态，不查询私人作业正文。刷新是实际读取，不通过动画或点击推定人数变化。

验收前教师逐项确认需求、测试依据、版本一致性。提交仍有缺口时，记录至少10字的具体例外理由，例如只验收设计阶段、实现和执行证据尚待补齐。这个决定不会更改测试结果，不能据此宣称所有用例通过。教师的人工勾选也不是平台自动证明语义完整。

## 验证及边界

`node scripts/teaching-local.mjs` 在隔离 PostgreSQL 和真实 HTTP 上验证首次/重复保存、双窗口及并发409、角色与跨班级、发布版本固定、仅新领取适用、显式采纳/保留、已提交保护、例外验收和离班。数据库触发器拒绝修改已发布版本。

`node scripts/teaching-full-ui-v7.mjs` 由API创建合成账号并仅在隔离库给予测试角色；其余业务操作通过网页完成：教师建班/发布，学生加入/领取/确认/计划/用例/文档，任务变更、旧依据失效、提交、人工反馈退回、修订重交和验收。模型为本地协议替身，未执行借用应用；测试保留阻塞与未执行。另注入一次503核对保存失败保留输入，双窗口实际409后比较保存。没有录屏或视频。

## 迁移和恢复

025为增量迁移：原任务成为v1、原领取固定v1，原项目、需求、提交快照及决定不改写；新增变更处理和评阅检查字段。升级前后核对记录数量与哈希指纹；不以清库或删除历史恢复。空库全部001—025及重复迁移均需验证。

API和前端必须配套升级。若出现问题，保留新增表和原数据，停止有问题的入口，回到已保存源码修复兼容性；不要把旧客户端直接连接新结构并逆向删除迁移。模型请求未知时不自动重发。恢复脚本和具体报告见CONTINUATION-V7与FINAL-REVIEW-V7。
