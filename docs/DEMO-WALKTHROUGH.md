# 工序智伴 6 分 40 秒竞赛演示路线

这是基于当前可运行功能的录制准备稿，不是已经录制完成的视频。官方截图要求：5—8 分钟、MP4、分辨率不低于 1080p、普通话讲解，包含项目介绍、核心功能和 AI 技术亮点。正式成片须另行录制、导出和检查。

## 贯穿场景

使用一个明确标注为“竞赛演示”的独立项目：**校园闲置书架**。让高职软件技术学生练习从模糊想法到需求、任务、审查、测试设计及文档的工程过程。示例项目本身不在本平台内运行，不将生成计划或测试用例称为完成了交易网站开发。

项目想法：学生可以发布闲置教材、查看书籍列表，并下架自己的书籍。希望有清晰的价格规则、数量限制和验收条件。第一版暂不做支付、聊天、物流和学校统一身份认证。

所有例子均为自行编写的演示输入。页面内的数量、时间、工具记录和模型结果使用实际运行数据，不提前编造。

## 普通话讲解提纲

**开场：**“工序智伴面向高职软件技术学生。很多同学可以写出一段代码，却不知道怎样把一个想法变成可验收的项目。我们把需求、知识、任务、审查、测试设计和文档放在同一条实训流程中，让每一步都能看见依据和结果。”

**需求：**“这里不是让 AI 直接替学生交作业。模型先给出需求草稿，学生可以修订，确认的版本才进入后续规划。比如第一版不接支付，并且要明确价格和发布数量的边界。”

**RAG：**“这份规则是演示时自行编写的资料。保存后平台解析和分块，再由本地中文向量模型建立索引。检索返回的是实际文档片段。我们可以展开来源核对，而不是因为有一个引用标记就认定答案一定正确。”

**Agent：**“现在看到的是实际工具执行记录。Agent 先检索知识，再生成任务，并检查结构、依赖和引用。计划需经过人工确认才能创建任务。依赖图来自模型返回并通过校验的任务关系；任务是否完成由实际实践和审核决定。”

**审查：**“这里明确分开两种结果：语法检查器确认的语法问题，以及模型提出的逻辑、性能或安全建议。当前样例语法正确，但数量限制可能存在边界问题。建议仍需要检查和测试，平台没有执行这段用户代码。”

**测试：**“生成用例以后，初始状态是未执行。我们筛选边界条件，并把暂时无法运行的用例登记为阻塞，同时写清原因。平台不会把生成成功当成测试通过。”

**文档与成长：**“文档草稿读取本项目已确认的需求、任务和人工测试记录。我们可以编辑、预览、保存和导出。成长中心展示真实操作和当前任务状态，不凭空生成能力分数。”

**结束：**“工序智伴的特点是把专业资料、实际工具记录和人工审核串起来，让软件工程训练可以检查、可以回看。当前 Agent 已实现检索、规划和校验；审查、测试设计与文档由用户发起。后续会继续完善跨阶段调度和课程资料评测。”

## 可直接使用的演示资料

文件名建议为 `校园闲置书架-演示规则.md`。以下内容是演示项目的自定规则，不是国家标准或教材原文：

```markdown
# 校园闲置书架：竞赛演示规则

本资料由演示团队自行编写，仅用于验证工程实训流程。

## 项目范围
学生发布闲置教材，查看书籍列表，并下架自己的书籍。
第一版不包含支付、即时聊天、物流或学校统一身份认证。

## 发布规则
1. 发布者必须登录。
2. 标题去除首尾空格后为 1—60 个字符。
3. 价格必须是有限的数字，且大于等于零；零元赠送允许发布。
4. 每人最多保留 3 条在售记录。已有 3 条时，不允许再创建第 4 条。
5. 只能修改或下架属于自己的书籍。

## 验收与测试设计
覆盖正常发布、零价格、负价格、非数字价格、空标题、61 字符标题、未登录、已有 2 条和已有 3 条、访问他人记录等场景。
生成测试用例后先标记未执行；未实际运行，不得记录通过。

## 文档要求
README 应写明范围、限制、真实环境和验证方式。
没有提供代码、真实 API 或部署地址时，应明确标记待补充，不编造实现事实。
```

## 录制前后验收

- 使用独立演示账号，项目名包含“竞赛演示”；不要使用真实学生隐私资料。
- 在本地工作台确认服务状态，并实际检查一次向量检索。密钥和配置文件不进入镜头。
- 录制电脑设为 1920×1080 或更高，先检查系统缩放、字体、浏览器视口与录屏画面。需要时使用“较大字号”和收起侧栏；窗口录制不能裁掉来源、工具记录或错误提示。
- 先走通完整路线，再录制正式讲解。保留实际失败并重试的证据；最终成片若省略等待或重试，明确交代。
- 结束后检查 MP4 格式、实际时长、分辨率、普通话声音清晰度、字幕与画面同步；从头到尾播放检查。
- 视频之外仍需交付可访问仓库、真实 Git 历史、完整 README/环境模板与不超过 30 页的技术 PDF。公网演示若提供，要保持评审期间可用并提供评审账号。
