# v6 教学流程、权限与恢复

目标是让软件工程实训中的需求、任务、测试与交付证据在换版后仍可核对。沿用同一个站点和登录入口，学生个人项目不因增加教师、管理员而自动共享。

所有注册账号默认只有学生能力。界面切换不能提权。每次请求重新检查当前角色/停用状态/班级关系；教师不获得学生项目的 GET 权限。管理员不等于业务数据超级用户。首次真实管理员和教师授权仍需用户指定准确账号并另行确认，本轮只在独立合成数据库授予测试角色。

## 最小闭环

1. 教师在 `/teaching` 创建班级，提供随机邀请码。保存任务为草稿，确认发布后学生才可见。
2. 学生在 `/classroom` 主动加入，领取任务，服务器幂等创建一个新的私有项目；既有个人项目不被归班。
3. 学生使用原需求/Agent/测试/追踪/文档模块完成项目。最新需求须确认后才能提交。
4. 提交预览给出真实缺口及原文。固定快照只含该版本需求、任务、测试、文档和人工关联，不包含私有知识、代码草稿或其他项目。学生明确共享后保存不可变提交版本。
5. 教师查看固定快照，逐条核对原文范围、关联修订、人工执行说明、文档来源变化。反馈草稿仅教师可见，修订使用预期修订号；AI 原文另存，不被教师改写覆盖。
6. 教师确认反馈后发布；决定退回或验收须另填理由和核对确认。验收决定不会把未执行/失败的测试自动改成通过。
7. 退回后学生修订并重新提交，旧快照和决定保留。旧窗口或旧提交的验收不能覆盖新提交。

每个提交集合最多1000项、固定快照最多1 MB，超出整份拒绝，不截断。需求最多50000字符，最新未确认草稿会阻止共享。AI点评完整快照最多18000字符，超限改为人工反馈。教师点评真实生成质量本轮未验证，合成协议测试不冒充真实点评。

## 并发、费用与恢复

- 领取、同一提交请求键去重；提交重新核对来源指纹与领取修订。相同提交键重复返回已有提交。
- 授权与教学变更使用短事务共享访问锁，等待者在取得锁后建立快照；网络/模型等待不占用该锁。老师和成员撤权后新请求失去访问。
- AI点评先持久保存请求键和生成状态。失败/超时/结果不确定不会自动再请求；相同键读取原状态。服务中断留下未完成记录，先检查后人工决定，不承诺撤销提供方已接收请求或费用。
- 月额度按 UTC 月计派发预留次数，含失败和不确定结果，不是美元预算或账单。共同模型入口和长规划工作器都绑定账号，事务内原子预留，超额在发送前拒绝；上调/停用与预留串行核对。
- 公共发布与审计在同一事务，内容哈希去重，同资料同版本不能覆盖。索引推理后、向量提交前重新检查维护权限；撤权则不写向量。原个人资料默认仍为 personal。
- 页面显式共享/验收不会作为导航“自动保存”。取消导航保留位置和输入，失败不会离开。保存中锁定相应输入，后端仍以修订/指纹做最后判断。

023 增加角色、账号控制、班级、成员、任务、领取、提交快照、反馈、决定、预算/回执和审计。024 增加公共资料范围、哈希、来源信息及导入状态。迁移是追加结构；001—024已在空库及重复迁移检查，不清空表。

本轮在主库应用前确认无排队/运行的 Agent 或长规划，前后只比较项目/需求/私人文档的数量，不导出正文。真实账号没有新增角色。出现问题可先停止相关入口、保留数据和日志，在新分支恢复旧代码核对；不要回滚删表或清理真实数据。旧v5包仍保留。新源码 ZIP 不含 `.env`、数据库备份、`.git`、运行日志或测试账号令牌。

验证入口：`pnpm verify`；`pnpm verify --suite=database`（现在强制独立数据库）；`node scripts/teaching-local.mjs --browser`（实际 HTTP/PostgreSQL/Edge，身份和点评均合成/替身）；`pnpm verify --suite=browser`。确切报告见 `verification/review-v6.json`，不把替身调用写成模型质量通过。
